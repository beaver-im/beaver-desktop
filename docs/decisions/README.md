# 第20章　设计决策记录（ADR）

ADR 记录重要边界、取舍与证据，不追认不存在的会议或推断作者动机。
当前两条是从源码/既有规则整理的“现状记录”，不是宣称在今天作出了新业务决策。

| 编号 | 状态 | 主题 |
| --- | --- | --- |
| [0001](0001-capability-boundaries.md) | 现有约束，已核对证据 | 能力包闭环与宿主组合边界 |
| [0002](0002-host-platform-binding.md) | 现状记录，已核对证据 | 宿主绑定平台与运行时能力注册 |
| [0003](0003-login-mode-switch.md) | 已接受，本轮实施 | 登录方式开关与两种登录组件的分工 |
| [0004](0004-module-tiering.md) | 提议，待裁决 | 模块分级与平台契约边界 |

## 使用规则

- 从 [TEMPLATE.md](TEMPLATE.md) 复制为下一个顺序编号 + 描述文件名，再加入索引。
- 新提案先标“提议”，不能把 AI 的建议直接标“已接受”；写明决策者/确认依据，未知则标待确认。
- 记录背景、选择、影响、替代方案、证据、验证和后续复审条件；历史动机缺失就写未知。
- 已接受决策被替换时保留旧页并标“被 ADR xxxx 替代”，不得悄悄改写历史。
- 只有包边界、存储协议、安全模型等长期选择需要 ADR；普通实现细节进模块指南，任务进度进 tasks。
- 现有约束变更同时核对根入口、模块指南和工具规则，避免三份相互矛盾。
