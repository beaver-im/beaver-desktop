# 第19章　开发闭环、测试与验收

最后核验：2026-11-22（Asia/Shanghai）。这是全仓长期执行标准。

最高原则：开源不运营，无历史包袱，不写/不留任何兼容代码，不因实现成本或改动面大妥协；发现问题直接整改，不需要的直接删除，并同步更新所有受影响调用方。

## 从任务到交付

1. **定位**：记录目标/非目标/验收；git status --short，git diff 与 git diff --cached 区分现有修改。不要恢复或暂存别人的文件。
2. **按需读取**：从[模块导航](modules/README.md)找到责任域，检索符号/接口并读局部源码；边界不清才扩大范围。
3. **实现**：先确认契约与副作用；跨进程同时改类型、handler、桥和调用者；持久化变更明确初始化/迁移策略。
4. **验证**：选最小充分检查集；先只读检查，再有必要的构建/运行。记录实际命令与工作目录、结果、限制。
5. **更新知识**：职责/入口/接口/命令变了，更新相应页面；结构性选择写 ADR；不要为一行样式更新整个知识库。
6. **交接**：未完成时按[模板](tasks/TEMPLATE.md)写下一步；完成时交付证据并归档。无复杂待办的微小任务可用最终交付说明，不强制新建任务卡。

## 命令事实源与副作用

根 [package.json](../package.json) 是脚本事实源，依赖须已就绪。下表命令均从仓库根执行（另有说明除外）。
占位符需替换为真实路径/包名；除文档检查外，这些命令没有因为被列出就代表已执行。

| 变更面 | 命令 / 核验 | 范围与限制 |
| --- | --- | --- |
| 纯文档/规则 | node scripts/check-knowledge.mjs；git diff --check | 只读，验证链接/路径/脚本与空白；不证明业务正确 |
| 单文件 TS/Vue | pnpm exec eslint <file> | 不加 --fix；路径和现有 lint 规则决定适用范围 |
| 平台类型 | pnpm --filter @beaver-im/beaver run tsc | 真实脚本为 tsc -p tsconfig.build.json；可能产生编译产物，不能误称 --noEmit |
| 宿主 main / IPC / 工具 | pnpm run build:main | 会写构建产物；Vite 构建不等于完整 TS/行为测试 |
| 宿主 renderer / 共享类型 | pnpm run build:renderer | vue-tsc --noEmit + Vite，类型过关后仍会写 dist |
| 指定能力包 | pnpm --filter <真实包名> run build | 先读其 package.json，不猜脚本或覆盖范围 |
| 本地能力装配 | pnpm run build:packages | turbo filter 有范围限制，参见[构建指南](modules/build-release.md) |
| 共享业务/UI 包 | pnpm --filter @beaver-im/beaver-biz run build；pnpm --filter @beaver-im/beaver-ui run build | 不假设 build:packages 包含二者；根据影响面选择 |
| 外置 AI / online | pnpm run build:ai；pnpm run build:online | 同级仓库 + 其依赖；跨仓改动分别验收 |
| 手工交互 | pnpm dev | 启动应用、连接服务并可能写本地数据；使用授权测试账号/隔离配置 |
| 根 lint 自动修复 | pnpm run lint | eslint . --fix，会批量改文件；不能当只读验收或无关任务默认步骤 |
| 安装包 | pnpm run package:win 或 pnpm run package:mac | 全链构建/打包，非普通任务默认验收；生产发布另需确认 |

根清单没有 test 脚本，也没有统一覆盖率门槛。不能执行不存在的 pnpm test 后说“测试完成”，不能以无 test 推断完全没有任何测试。
涉及外置仓测试应先读它的清单并记录工作目录；本仓检查不代替对端测试。
未来新增自动化测试时把真实命令加入本表和 [knowledge-checks.json](knowledge-checks.json)，不要只写愿景。

## 风险导向验收

- IPC/账号：非法参数、错误返回、退出换号、窗口关闭监听释放。
- 消息/同步：ACK/超时、重连、重复/乱序、同步中流式消息、隔离用户库。
- 表/存储：空库、已有库、字段默认/幂等、回滚或恢复策略；不动真实用户数据。
- 能力包/平台：公开导出一致性与全部消费者同步、激活顺序、失败隔离、窗口资源路径、废弃接口清理。
- 本机工具：越界/权限、无效参数、超时取消、日志脱敏；不执行真实危险动作验证。
- UI：空/加载/错误状态、会话切换、交互可访问性、系统平台差异。

## 证据格式与完成标准

每次交付说明：变更文件/行为 → 运行的命令与目录 → exit/关键结果 → 未运行及原因 → 剩余风险。
复现手工检查要写步骤与观察，不能只写“看起来没问题”；失败检查区分既有基线问题与本次新增。
对未覆盖的集成/平台不要标通过；只有验收满足、知识同步且无误覆盖现有工作才称完成。

## 新鲜度与评审

变更者维护相关指南/ADR/检查清单；评审者核对证据，至少运行文档检查和 diff --check。
每页的核验日期只在相应事实重新确认时更新；架构与长期规则不记录临时分支进度。
人工评审语义和约束，脚本检查可机械验证的路径和脚本名；未来可接入 CI，但本次不虚构已有 CI。

## 19.1 所有变更与重构需要什么测试证据

测试不是“跑一个命令”这件事，而是能重复证明一个具体行为。按风险选下面的层，不强加虚构覆盖率。

| 变更 | 至少设计的用例 | 应放在哪里 / 如何交付 |
| --- | --- | --- |
| 纯转换/校验/状态计算 | 正常、空值、非法输入、边界值 | 邻近所属模块的测试；使用该模块真实已有运行器，不假设根有 pnpm test |
| API / IPC 边界 | 合法、格式错、未授权、失败、超时/取消 | 适配层契约测试或隔离的可复现步骤；不调用真实危险能力 |
| SQLite 结构/同步 | 空库、旧结构、重复回放、失败恢复、游标推进 | 临时库与固定输入；不拿用户聊天库做实验 |
| Vue 页面/状态 | 空/加载/失败、切换竞态、事件与销毁 | 可用的组件测试加实际交互步骤；类型检查不代替交互 |
| 插件生命周期 | 启用/禁用、缺包、中途失败、开关重开 | 真实装配检查与资源计数/观察，标明平台与环境 |

目前根清单没有统一测试运行器；新增测试前先确认所属包的工具和脚本。
不要为了“有测试”放入根本跑不起来的 .test.ts。若需引入运行器/依赖，单独说明选择与命令并取得本任务相应授权；
本轮手册建设没有安装或配置运行器。暂时只能手工验证时记录具体输入、操作、预期和实际结果，并把自动化缺口列为风险，不能冒称单测通过。
对数据安全、权限或协议完整性缺乏证据的变更，不以“没有测试环境”直接宣布行为验收完成。

## 19.2 评审者可以直接打勾的清单

- [ ] 第2章：新文件归属、命名、别名正确，没有跨包深导入或无必要的新框架；业务子包三层/可选 preload 按[2.5](standards/01-boundaries-and-naming.md)核对。
- [ ] 第3章：请求/响应类型清晰；未知输入先校验；any 和断言没有掩盖边界错误；main 对外能力有显式接口及精确 Api 后缀，导出/依赖方向符合[3.5](standards/02-types-and-api.md)。
- [ ] 第4章：组件只负责表现/交互；共享状态位置清楚；没有页面直写数据库或另建核心连接。
- [ ] 第5章：IPC 的请求、桥、可信入口、业务实现、响应和订阅清理都齐全，权限不只在 UI。
- [ ] 第6章：表定义/初始化/升级/持久服务/同步/通知同时考虑，重复与失败路径有证据。
- [ ] 第7章：副作用在生命周期内，装配期与运行期错误区分，资源拥有者清楚。
- [ ] 第8章：错误不被吞掉伪装成功，日志脱敏，监听/句柄/计时器可以释放。
- [ ] 兼容与清理：没有为兼容旧版/旧数据新增兼容代码、双轨分支或保留不需要的文件/路径；所有受影响调用方已同步更新。
- [ ] 本章：记录实际命令与结果；明确未跑的自动化/集成/平台；相关知识和交接已更新。

不适用的检查写 N/A 和原因，不为文档/样式任务硬跑数据库或整套发布流程。
清单是人工评审工具；当前文档校验脚本不自动证明这些业务规范全部满足。
