# 海狸桌面端工程手册

这本手册回答三件事：**项目怎么组织、代码应该怎么写、新功能应该怎么加。**
适用目录：beaver-desktop。最后核验：2026-11-22（Asia/Shanghai）。

## 最高工程原则：无历史包袱，不留兼容代码

本项目为开源项目且不作商业托管运营，**没有历史包袱**：

- **不考虑任何兼容代码**：不写、不留仅服务旧版本接口、旧数据格式或旧路径的兼容层、双轨过渡、适配壳或兜底分支。
- **不考虑实现成本**：不因改动面大或图省事妥协设计，不做“先将就、以后再迁”的权宜方案。
- **哪里有问题就改哪里，不需要的去掉**：契约、目录、接口与数据模型可直接破坏性调整，同时同步更新全部受影响调用方，删除废弃实现与冗余路径。
- **边界不放松**：仍须遵守进程隔离、权限与输入校验、正确错误处理、测试验证；对他人未提交改动及真实本地库/隐私数据的操作仍需授权，不能把“不运营”误解为没有敏感数据。

## 怎么读这本书

- **第一次接手**：第1章看全貌 → 第2章决定代码放哪 → 第3～8章了解写法 → 选第9～11章跟做一次 → 第19章验收。
- **做具体任务**：下方任务导航选章节，不必每次读整本；第12～18章用于定位源码。
- **评审代码**：先按第2～8章的“评审检查”看边界与写法，再按第19章核对真实验证证据。
- **AI 接手**：从根 [AGENTS.md](../AGENTS.md) 进入，只打开相关章节；本书不是每次都要注入的长提示词。

## 规则的含义与维护

每章区分：**当前事实**（已核查现状）、**统一工程规范**（全仓唯一目标，有问题直接按规范整改，不留兼容层）、**未整改差异**（现状尚未全部达标，不得冒充已修完）。
章节中的“必须/禁止”约束新增和本次修改的代码；不授权批量改名、清库或迁移老业务。
代码块会标“真实摘录”或“写法示例/伪代码”；后者不代表仓库已有对应 API。

源码、清单和构建配置是实现事实源；第2～8章是全仓编码与重构的统一规范正文；模块参考只帮助定位；任务卡只记录进度。
修改入口、契约、目录或命令时，同次更新对应章节；重要取舍留 ADR，未知历史动机不要补故事。
工具适配文件只指向这份知识，不维护另一套正文。工具的自动加载各有差异，没有永久记忆承诺。

`node scripts/check-knowledge.mjs` 检查文档链接、路径、脚本和目录完整性；**它不检查业务代码是否符合所有规范，也不是安全审计、编译或业务测试。**
